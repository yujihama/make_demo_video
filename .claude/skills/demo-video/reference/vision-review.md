# 見た目の審査の手順（Claude Code が審査者になる）

`--vision` を付けた `make` / `review` / `loop` / `vision` は、完成動画の要所のコマを書き出して止まる（終了コード 3）。
あなたが映像ディレクターとして各コマを見て、視聴者の理解を妨げる問題と直し方を `response.json` に書く。
好みの問題（色味の好き嫌いなど）は指摘しない。

## 1. 依頼を読む

依頼フォルダ `out/<id>/_handoff/vision-<シーン>-<言語>-<ハッシュ>/` の中身:

| ファイル | 内容 |
|---|---|
| `request.md` | 動画の題名、字幕の言語、コマの一覧（コマ番号・秒・ステップ番号・種類・見せ場・そのコマで出ているはずの文言）、観点、回答の書き方 |
| `sheet.jpg` | 全コマの一覧（左上の `#番号` がコマ番号） |
| `image_NN.jpg` | 各コマ（1280x720） |
| `schema.json` | 回答の形 |

## 2. コマを見る

1. `sheet.jpg` を開いて全体の流れをつかむ
2. コマを1枚ずつ開く（`image_00.jpg` から順に）。`request.md` のそのコマの行を横に置き、「見せ場」と「出ているはずの文言」を確かめながら見る
3. 気になる箇所は、必要なら画像を切り出して拡大して確かめる（例: Python で PIL を使って crop → resize）。縮小表示では細い線や記号（`_` など）が消えて見えることがあるので、指摘の前に拡大で確かめる

## 3. 観点

| category | 見ること |
|---|---|
| `caption_occlusion` | 字幕・吹き出し・数え上げが、そのコマで見せたい操作対象・結果・数値を隠していないか |
| `readability` | 字幕・カード・アプリの画面の文字が読める大きさと濃さか |
| `emphasis_target` | 波紋・スポットライト・吹き出し・数え上げが、字幕が説明している対象を正しく指しているか |
| `content_mismatch` | 字幕の内容と、そのコマの画面の内容が食い違っていないか（例:「6件」と言っているのに画面は別の数） |
| `framing` | カメラの寄りで、見せたい情報（表の列・数値・ボタン）が画面外に切れていないか |
| `layout` | カードや字幕の文字が枠からはみ出したり、重なったり、途中で切れたりしていないか |
| `language` | 字幕・カードが指定の言語か（アプリの画面そのものは元の言語のままでよい） |

## 4. 重さ

| severity | 目安 | 判定への影響 |
|---|---|---|
| `high` | 伝えたいことが伝わらない（数値が隠れて読めない、別の物を強調している、文字が切れている、言語が違う） | 1つでもあれば不合格 |
| `medium` | 伝わるが見づらい、誤解しかねない | 合格扱い。ただし直し方（fix）があれば `loop` が反映して、もう一度撮って確かめる |
| `low` | 直すとよりよい | 記録のみ |

`high` が1つでもあれば `overall` は `"fail"`、無ければ `"pass"`。

## 5. 直し方（fix）

自動で直せるものは `fix` に入れる。直し方が決まらないもの、コードを直す必要があるものは `fix: null` にして `suggestion` に書く。

| path | value | 反映先 |
|---|---|---|
| `hold` | 追加するミリ秒（例 `"800"`） | シーン YAML のそのステップ |
| `caption` | 新しい字幕（指定の言語。`**語**` 可） | 元の言語ならシーン YAML、それ以外は翻訳ファイル |
| `effect.zoom` | `"out"` / `"fit"` / `"focus"` / `"1.2"` など | シーン YAML |
| `effect.spotlight` / `effect.ripple` | `"false"` | シーン YAML |
| `effect.callout` | 新しい吹き出しの文（指定の言語） | 元の言語ならシーン YAML、それ以外は翻訳ファイル |
| `style.max_zoom` | `"1.3"` など（`step` は `null`） | シーン YAML |

- `step` は `request.md` のコマ一覧にあるステップ番号を入れる（分からなければ `null`）
- 字幕を短くするときは、意味を落とさず1行に収まる長さにする（1080p で日本語およそ 38 字、英語およそ 70 字が1行）
- 同じ問題が複数のコマに出ていても、指摘は1つにまとめる

## 6. 回答を書く

`response.json` の例:

```json
{
 "overall": "pass",
 "summary": "章カード・字幕・数え上げ・比較カードとも読みやすく、強調も正しい対象を指している。処理中の2行字幕が結果の見出しを覆う点だけ直したい。",
 "findings": [
  {
   "frame": 5,
   "step": 4,
   "severity": "medium",
   "category": "caption_occlusion",
   "problem": "処理中の字幕が2行になり、完了と同時に現れる結果の見出しと表の先頭を覆っている",
   "suggestion": "字幕を1行に収まる長さに縮める",
   "fix": {"path": "caption", "value": "**承認漏れ・自己承認・高額取引**を自動で検出"}
  }
 ]
}
```

- `summary` は審査全体の一言（何が良く、何を直すべきか）
- 問題が無ければ `findings` は空配列、`overall` は `"pass"`
- 書いたら、止まったコマンドを再実行する（`loop` は `--resume`）。スキーマに合わなければエラーで止まるので直す

## 7. 審査のあと

- 再実行すると `build*/vision.json` に審査結果が保存され、`review*.json` の `vision` にも入る
- `loop --vision --resume` は `high` と `medium` の直し方を反映して次の回へ進む。新しい回ではコマが変わるので、再び止まったら同じ手順で審査する（前の回で直した点が直っているかも見る）
- 最終報告では、最後の回の `summary` と、残った `low` の指摘をユーザーに伝える
